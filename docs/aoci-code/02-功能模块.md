## 一、接入与接口层

### 1.1 `internal/cli` — 命令行入口（52 个文件，最大包）

`cmd/aoci/main.go` 只有一件事：启动进程 → 交给 CLI root command → 把错误映射成退出码。**MCP stdio 的 stdout 保留给 JSON-RPC，所有日志必须走 stderr**。

## 三、治理事务层

### 3.1 `internal/cognitiontxn` — 认知事务（1 个文件，最核心的原语）

`transaction.go` 定义统一提交边界。所有正式写入（Volume Apply + Baseline 更新 + Scope 投影）**要么作为同一事务的一致结果发布，要么进入可证明的 Recovery**。

不允许「文件已成功但其他 Volume 无基线」的半完成状态。

### 3.2 `internal/fs` — 安全文件操作（31 个文件）

写入安全的地基，平台差异全在这里：

| 文件组 | 职责 |
|---|---|
| `atomic.go` | 原子写入 + 禁止覆盖的恢复移动 + **持久化替换 CAS** + 创建 CAS |
| `atomic_exchange_{linux,darwin,windows,other}.go` | 平台原子交换（`renameat2(RENAME_EXCHANGE)` / `renamex_np(RENAME_SWAP)` / `ReplaceFile`） |
| `atomic_create_*.go` | 平台原子创建（O_EXCL 语义） |
| `lock.go` + `owner_*.go` + `lock_owner_open_*.go` + `process_identity_*.go` + `process_identity_compare.go` | **跨进程锁 + 进程身份校验（防 PID 复用）** |
| `safe_inventory.go` + `safe_inventory_platform_*.go` | 安全清单（可移植文件名/路径校验） |
| `safe_path.go` | 路径穿越防护 |
| `git_command*.go` / `git_ignore.go` / `git_head.go` | Git ignore 权威查询、HEAD 查询（scan 的唯一文件来源） |
| `walk.go` | 目录遍历 |
| `countlines.go` | 行数统计（E 规模轴） |
| `retention.go` | 草稿/事务/恢复证据的保留策略 |

**核心不变量**：原生发布绝不会降级为覆盖式重命名；遇到竞态、不安全类型或无法验证的字节时，**必须保留第三方状态并失败关闭**。

## 六、核心状态机

### 6.1 对齐状态

```
                    ┌─────────────┐
    零 Entry 骨架 ──▶│  unbaselined│──scan──┐
                    └─────────────┘         │
                                            ▼
    ┌──────────────┐  maintain  ┌────────────────────┐
    │ authoring_    │◀──────────│   baselined         │
    │ required      │           │   (有 Entry 但未对齐)│
    └──────┬───────┘           └─────────┬──────────┘
           │ 模型创作 + Apply              │
           ▼                             ▼
    ┌──────────────┐  最后一块 Apply  ┌──────────┐
    │ aligned      │◀────terminal_proof│  ...    │
    └──────────────┘                  └──────────┘

   其他状态：evidence_required / observed_pending / scope_change_required /
            cognition_budget_exceeded / stopped（失败关闭）
```

`exit_code=0` **仅当**每个启用 domain 都 aligned 且无 scope/observe/budget 阻塞发现。

### 6.2 Maintain 循环（无参数调用）

```
aoci_maintain()
   │
   ├─ 服务器读当前仓库状态，算出「当前完整批次」
   ├─ 返回 next_action 之一：
   │    · authoring_required  → 给批次 + 创作合同，模型写 Entry
   │    · evidence_required   → 需要数据库 Evidence
   │    · review_observed     → 有 observe 变更待人工复核
   │    · aligned + terminal_proof → 收工
   │    · none                → 无事可做
   └─ 模型按 next_action 执行后，再调 aoci_maintain() 拿下一批
```

**关键**：不要在包装脚本里复制这个状态机。权威状态机在运行中二进制（`index agent guide --json`）。

### 6.3 Whole-Index 交付链

```
aoci_overview()  ──▶ Chunk 1 (含 next_cursor)
      ▲                    │
      │                    ▼
      │            Agent 顺 next_cursor 读到底
      │                    │
      │                    ▼
      └──── Challenge ◀── Attestation 提交
                    │
                    ▼
              receipt（会话级身份）

异常分支：
  · check_only=true        → 紧凑检查点（不能替代完整交付）
  · 上下文压缩后           → 必须重新完整 Overview，probe 不算
  · 装不进上下文           → delivery_mode=capacity_stop，降级 source-bound，不循环
  · 有 Pending Recovery    → 失败关闭，不混合内容
```
